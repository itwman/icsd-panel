# راهنمای نصب پنل ICSD نسخهٔ ۲

## پیش از شروع

| چه چیزی | توضیح |
|---|---|
| یک سرور برای پنل | Ubuntu 22.04+ یا Debian 12+. Docker لازم نیست. پنل حدود ۶۰ مگابایت RAM مصرف می‌کند. |
| یک زیردامنه | مثلاً `panel.icsd.ir` با رکورد A به IP همان سرور. |
| دسترسی root به هر سرور | برای اجرای اسکریپت نصب پنل و دستور نصب agent. |

> **سرور پنل بهتر است خارج از ایران باشد.** تلگرام، Go و بسته‌های پایتون از داخل ایران همیشه در دسترس نیستند.
>
> agent سرورهای داخل ایران فقط باید به آدرس HTTPS پنل برسد. در قطعی اینترنت بین‌الملل، خود پنل هم از ایران باز نمی‌شود.
> پس از وصل شدن دوباره، agentها تا ۱۰ دقیقه دادهٔ عقب‌مانده را می‌فرستند.

---

## ۱. نصب پنل (بدون Docker، کنار سایت‌های موجود)

روی سرور پنل با root:

```bash
cd /opt
git clone https://github.com/itwman/icsd-panel.git
cd icsd-panel
bash deploy/install-hub.sh --domain panel.icsd.ir --email farshplusiran@gmail.com
```

> اگر مخزن خصوصی است، `git clone` نام کاربری و رمز می‌خواهد. به‌جای رمز، یک Personal Access Token گیت‌هاب بدهید.
> مخزن حتماً باید در `/opt/icsd-panel` باشد.

اسکریپت به ترتیب این کارها را می‌کند:

1. پیش از هر تغییری بررسی می‌کند که پورت 8088 آزاد باشد و nginx سایتی با همین دامنه نداشته باشد.
2. فقط بسته‌هایی را که نیست نصب می‌کند (`python3-venv` و `curl`).
3. کاربر `icsd` و محیط پایتون جدا (`/opt/icsd-panel/.venv`) می‌سازد. داده در `/var/lib/icsd-hub` نگه داشته می‌شود.
4. Go را موقتاً دانلود می‌کند، agent را می‌سازد و Go را پاک می‌کند.
5. سرویس `icsd-hub` را راه می‌اندازد که فقط روی `127.0.0.1:8088` گوش می‌دهد.
6. در nginx **یک فایل سایت جدید** می‌سازد: `/etc/nginx/sites-available/icsd-panel.conf`.
   - اول `nginx -t` را اجرا می‌کند. اگر خطا بدهد، فایل را برمی‌دارد و هیچ چیزی عوض نمی‌شود.
   - به سایت‌های دیگر دست نمی‌زند.
7. با certbot برای همین دامنه گواهی SSL می‌گیرد. اگر certbot نصب نباشد، نصبش می‌کند.

گزینه‌های دیگر:

- `--no-nginx`: به nginx دست نمی‌زند و تنظیمات لازم را چاپ می‌کند.
- `--no-ssl`: certbot را اجرا نمی‌کند.
- `--port 8090`: اگر 8088 گرفته است، پورت دیگری می‌گذارد.

### نصب با Docker (برای سروری که Docker دارد)

```bash
cd /opt/icsd-panel/deploy
cp .env.example .env && nano .env       # ICSD_DOMAIN و ICSD_PUBLIC_URL
docker compose --profile caddy up -d --build
```

- `--profile caddy` فقط وقتی است که پورت‌های 80 و 443 آزاد باشند.
- اگر روی سرور وب‌سرور هست، `--profile caddy` را بردارید. پنل روی `127.0.0.1:8088` گوش می‌دهد.
- در این روش، جای `sudo icsd-hub` بنویسید `docker compose exec hub icsd-hub`.

## ۲. ساخت حساب مدیر

```bash
sudo icsd-hub create-admin
```

نام کاربری و رمز (دست‌کم ۱۰ نویسه) را می‌پرسد. **رمز پیش‌فرضی وجود ندارد.**

## ۳. اولین ورود

`https://panel.example.com` را باز کنید و وارد شوید. پنل از شما می‌خواهد **رمز دوم (2FA)** را فعال کنید:
کد QR را با Google Authenticator، Microsoft Authenticator یا Aegis اسکن کنید و کد ۶ رقمی را وارد کنید.

## ۴. افزودن سرورها

برای هر سرور، **از جمله خود سرور پنل**:

1. در پنل «افزودن سرور» را بزنید و یک نام بدهید.
2. دستوری را که نشان می‌دهد کپی کنید. شکلش این است:
   ```bash
   curl -fsSL https://panel.example.com/install.sh | sudo bash -s -- --token ...
   ```
3. با SSH وارد آن سرور شوید و دستور را اجرا کنید. چند ثانیه بعد سرور در داشبورد «آنلاین» می‌شود.

این دستور چه می‌کند:

- agent را از خود پنل دانلود می‌کند و checksum آن را بررسی می‌کند.
- کاربر بدون دسترسی `icsd-agent` را می‌سازد و اگر Docker نصب است، آن را به گروه `docker` اضافه می‌کند.
- یک سرویس systemd محدودشده راه می‌اندازد که فقط می‌خواند.

نکته‌ها:

- **هیچ پورتی باز نمی‌شود** و هیچ بسته‌ای نصب نمی‌شود.
- توکن یک‌بارمصرف است و ۲۴ ساعت اعتبار دارد.
- برای اینکه agent به Docker دسترسی نداشته باشد، در انتهای دستور `--no-docker` بگذارید. عضویت در گروه docker عملاً معادل root است.

## ۵. اعلان‌ها (بله و تلگرام)

تنظیمات ← اعلان‌ها:

- **بله** (از داخل ایران در دسترس): در بله با `@botfather` ربات بسازید و توکن را وارد کنید. به ربات پیام بدهید.
  شناسهٔ چت را از `https://tapi.bale.ai/bot<توکن>/getUpdates` بردارید.
- **تلگرام:** با `@BotFather` ربات بسازید. شناسهٔ چت را از `https://api.telegram.org/bot<توکن>/getUpdates` بردارید.

سپس «ذخیره و ارسال پیام آزمایشی» را بزنید.

پنل روی سرور خارج است. تلگرام از آن‌جا همیشه کار می‌کند، ولی ممکن است بله از خارج پیام نپذیرد.
هر دو را فعال کنید و با پیام آزمایشی ببینید کدام می‌رسد.

## ۶. پایش آدرس‌ها

در «پایش آدرس‌ها» آدرس سایت‌ها را اضافه کنید، مثلاً `https://farshplus.ir/`.
پاسخ 5xx، قطعی یا نبودن عبارت مورد انتظار در صفحه یعنی خرابی. تاریخ انقضای SSL هم هر ۶ ساعت بررسی می‌شود.

## ۷. مدیریت سرورها (فایل، سرویس، دیتابیس، SSL، بک‌آپ)

agent به‌طور پیش‌فرض در حالت **مدیریت** نصب می‌شود. سرورهایی که با نسخهٔ ۲.۰ نصب شده‌اند فقط مانیتور می‌کنند؛
روی هر کدام یک بار اجرا کنید:

```bash
curl -fsSL https://panel.icsd.ir/install.sh | sudo bash -s -- --upgrade
```

آنچه پنل روی هر سرور مجاز است، در همان سرور در `/etc/icsd-agent/policy.json` است و فقط root همان سرور می‌تواند عوضش کند:

| کلید | پیش‌فرض | یعنی |
|---|---|---|
| `files.roots` | `/var/www`، `/opt`، `/srv`، `/home` | پوشه‌هایی که فایل منیجر می‌خواند و می‌نویسد |
| `files.readonly` | `/etc/nginx`، `/var/log` | فقط خواندنی (برای دیدن پیکربندی و لاگ‌ها) |
| `services` | nginx، php-fpm، MySQL، PostgreSQL، Redis، gunicorn… و سرویس‌های سایت‌های پایتونی این سرور | سرویس‌هایی که می‌شود شروع، توقف یا ری‌استارت کرد |
| `docker` | `true` اگر Docker نصب است | کنترل کانتینرها |
| `databases` | `true` | فهرست، بک‌آپ و بازگردانی دیتابیس‌ها |
| `ssl` | `true` | فهرست، تمدید و گرفتن گواهی |
| `console` | `false` | اجرای دستور دلخواه با root؛ فقط اگر واقعاً لازم است روشن کنید |
| `backup_dir` | `/var/backups/icsd` | محل بک‌آپ‌ها (فقط root می‌خواند) |

بعد از ویرایش: `systemctl restart icsd-agent`.

چیزهایی که پنل هرگز به آن‌ها دست نمی‌زند، صرف‌نظر از policy:

- `/etc/icsd-agent`، `/etc/shadow` و `sudoers`
- هر پوشهٔ `.ssh` و `.gnupg`
- فایل‌های پنهان پوشهٔ خانهٔ کاربران (`.bashrc` و…)
- سرویس‌های sshd، فایروال، systemd و خود agent

> هر کاری که در policy مجاز باشد، از پنل انجام‌شدنی است. اگر کسی به پنل نفوذ کند، همان کارها را هم می‌تواند بکند.
> پس فقط چیزی را مجاز کنید که لازم دارید، برای پنل رمز دوم را حتماً روشن نگه دارید و دسترسی مدیر را به افراد کم بدهید.
> اگر روی سروری فقط مانیتورینگ می‌خواهید، agent را با `--monitor-only` نصب کنید.

## به‌روزرسانی

```bash
cd /opt/icsd-panel
git pull
bash deploy/install-hub.sh --upgrade
```

در نصب با Docker، به‌جای دستور سوم این را اجرا کنید: `cd deploy && docker compose --profile caddy up -d --build`.

اگر صفحهٔ سرور گفت agent قدیمی است، روی همان سرور اجرا کنید:

```bash
curl -fsSL https://panel.example.com/install.sh | sudo bash -s -- --upgrade
```

## پشتیبان از دادهٔ پنل

همهٔ داده (کاربران، سرورها، تاریخچه) در `/var/lib/icsd-hub/hub.db` است:

```bash
systemctl stop icsd-hub
tar czf /root/icsd-hub-data.tgz -C /var/lib/icsd-hub hub.db
systemctl start icsd-hub
```

## رفع اشکال

| مشکل | راه‌حل |
|---|---|
| سرور «قطع» است | روی آن سرور: `systemctl status icsd-agent` و `journalctl -u icsd-agent -n 50` |
| پنل باز نمی‌شود | روی سرور پنل: `systemctl status icsd-hub` و `journalctl -u icsd-hub -n 50` |
| گوشیِ رمز دوم گم شده | `sudo icsd-hub reset-2fa <نام کاربری>` |
| رمز فراموش شده | `sudo icsd-hub set-password <نام کاربری>` |
| کانتینرها دیده نمی‌شوند | Docker بعد از agent نصب شده؛ دستور نصب را با `--upgrade` دوباره اجرا کنید |
| برداشتن agent | `curl -fsSL https://panel.example.com/install.sh \| sudo bash -s -- --uninstall` |
| «تلاش ناموفق زیاد» | ۱۵ دقیقه صبر کنید؛ ورود از آن IP یا با آن نام کاربری موقتاً بسته شده است |
